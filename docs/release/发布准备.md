# 新架构发布与验收

本目录中的 [v1.2.0.0 预发布文案](v1.2.0.0-预发布草稿.md) 保留发布前的审阅稿；当前状态和正文以 GitHub Release 为准。未来发布可复制 [下载徽章模板](下载徽章模板.md)，将 `<版本号>` 和 `<标签>` 替换为实际值，并核对文件名与发布资产完全一致。

## 已准备的平台

| 平台 | 资产 | 用途 |
| --- | --- | --- |
| Windows x64 | `SVL.Desktop_v<版本号>_Release.exe` / `SVL.Desktop_v<版本号>_Debug.exe` | 自带运行环境的单文件，也供旧 WPF 更新器使用；不是安装向导 |
| Windows x64 | `SVL_v<版本号>_Windows_x64_requires_dotnet10.exe` / `SVL_v<版本号>_Windows_x64_requires_dotnet10_diagnostic.exe` | Release / Debug 轻量单文件 |
| macOS Apple Silicon / Intel | `SVL_v<版本号>_{release\|debug}_macOS_{arm64\|x64}[_requires_dotnet10].dmg` | 两种构建配置和运行时类型的拖放安装包 |
| Ubuntu / Debian x64 | `svl-launcher_<版本号>[.debug]_amd64[_requires_dotnet10].deb` | 两种构建配置和运行时类型的系统安装包 |
| Linux x64 | `SVL_v<版本号>_{release\|debug}_Linux_x64[_requires_dotnet10]` | 两种构建配置和运行时类型的免安装单文件 |

文件名带 `_requires_dotnet10` 的轻量版本需要预装对应架构的 .NET 10 Runtime；轻量 DEB 声明 `dotnet-runtime-10.0` 软件包依赖，发行版软件源须提供该包。Release 和 Debug 的 DEB 使用同一包名 `svl-launcher`，安装其中之一即可；Debug 包内部版本使用 `~debug` 时，从 Release 切换可能需要允许降级。Linux 免安装程序下载后需要先赋予执行权限。

构建 Debug 时可设置 MSBuild 属性 `DebugType=embedded`，将应用调试符号嵌入程序；运行单文件不需要另行分发 PDB。Windows 轻量 EXE 文件名不能含 `Release` 或 `Debug`，否则旧 WPF 更新器可能误选轻量版。当前 Avalonia 更新器仍按构建类型和平台筛选资产：发布 Windows 轻量 ZIP、Linux 自带环境和轻量 ZIP 时，应保留对应的 `release` / `debug` 名称，以便已发布版本识别。旧版 Release 和 Debug 各只能有一个匹配其构建类型的 EXE。

此外，发布页应附带 UTF-8 编码的 `update.txt`，供旧版更新窗口显示简短更新说明。不要把 ZIP 改名为 EXE；旧版更新器直接运行下载到的 EXE。

新版更新弹窗优先读取 `update.txt`（文件名大小写不敏感），获取失败或未提供时回退到 Release 正文。发布包写入自身运行时类型，自动检查只选取相同类型的下载资源；没有对应资源或无法识别当前类型时提示手动选择。Windows 支持应用内替换，macOS 和 Linux 当前仍需手动安装。

## 发布前检查

1. 确认版本号、发布标签、`SVL.Avalonia.csproj` 和 `build.ps1` 一致；所有包必须来自同一份已审阅源码。
2. 执行构建与隔离测试，检查 GitHub Actions；测试不得清理真实用户的配置、实例或缓存。
3. 检查安装包的架构、安装入口、校验和与各平台依赖。macOS 当前为 ad-hoc 签名，未完成 Apple 公证；Apple Silicon 使用 Intel SteamCMD 时需要 Rosetta 2。
4. 在 Windows、macOS 和 Linux 分别验证启动、路径选择、游戏 / SMAPI 安装、Mod 管理和网络下载；用真实 Nexus / CurseForge 账号补充端到端验收。
5. 验证匿名统计服务可用、旧版标识不会因迁移变化；不要用新造的标识污染线上统计。
6. 创建 GitHub **Draft + Pre-release**，上传对应资产和 `update.txt`，先审阅文案与资产。草稿中的下载链接在公开发布前不能用于公开下载。
7. 文案通过审阅后再发布预发布；在公开发布之后验证每个徽章链接、资产校验和及下载文件。
8. 检查正式发布的 `update.txt` 能被旧版和新版读取；使用下一版本的测试 Release，分别验证两种包体选择同类型资源。测试 macOS / Linux 时还需手动完成安装。

## 旧 WPF 版直接升级测试

草稿不会出现在普通的公开 Release 查询中，因此必须在预发布公开后才能完成真实在线更新测试。测试前使用隔离的旧版程序副本与测试配置，备份用户配置、实例列表和重要游戏数据。

1. 以旧版 Windows Release 启动测试副本，记录旧版程序版本、配置及实例列表。
2. 在旧版设置中将首选更新源设为 GitHub，启用“检查预发布版本”，然后手动检查更新。旧版默认不包含预发布；首选 Gitee 时可能先找到 Gitee 的旧版本。
3. 确认旧版选择 `SVL.Desktop_v<版本号>_Release.exe`，下载、重启并启动新版。
4. 确认配置、实例列表和独立启动设置迁移正确，原有游戏与 Mod 文件未被移动；再次启动检查不会重复迁移。
5. 记录升级前后程序路径、版本、日志及失败现象。若升级失败，保留旧版与测试数据，不以真实玩家环境反复覆盖。

## 匿名用户统计口径

启动器默认每天按 UTC 日期上报一次匿名安装标识的 SHA-256 值和基本运行信息，服务按标识去重。累计数更接近匿名安装数，24 小时活跃数基于收到的上报，而不是实时在线人数。环境变量 `SVL_DISABLE_ANON_TELEMETRY=1` 可关闭上报；服务不可用时不影响启动，下次启动可重试。

统计服务位于独立的 `SVL-Website` 仓库。当前服务将整份统计状态读出、修改后写回 KV；并发请求可能互相覆盖。读取异常可能被当作空状态，写入失败也可能没有传递给上报接口，因此成功响应不能证明每次都可靠持久化。应在独立后端修复和部署后再验收统计准确性，本次启动器兼容修复不能消除这些服务端风险。
